Краткое описание основных элементов диаграммы
Автор — создает и публикует главы книг.
Рецензент — рецензирует опубликованные главы, оставляет комментарии.

Платёжная система — внешний сервис для приёма платежей.
Сервис уведомлений — внешний сервис, который рассылает email или push-уведомления.

## Диаграмма контейнеров

![fLL1Rnj55BxxLmmvkLAIlN3Yr3QD1AWDIspWM8tjQJ9YlRkQ7IS4X9G4Mf1i4T8B5OS2GeYhxIHuRSVhlp3xZ_ZchRrUuvWUSeayRz_xvdlV-zxaOQIvqgscLtfF-dMlrH3iKEim-i1n53_UFf3wi5LhHKBL0ryBNs_NWwQpB-jSDO8zAKBXEJllRxaUz_LdpvuwJHvfeH1wleDyBdsXja](https://github.com/user-attachments/assets/55f8efbb-46b7-4944-b9c1-39421e1b9c31)
Краткое описание основных элементов диаграммы
Веб-приложение (WebApp) — отвечает за пользовательский интерфейс (HTML-страницы, формы). Пользователи (авторы, рецензенты, издатели, клиенты) работают с системой через веб-браузер.
API (ASP.NET Core Web API) — реализует бизнес-логику, обрабатывает запросы от веб-приложения, взаимодействует с базой данных и внешними системами (платёжная система, сервис уведомлений).
База данных (SQL Server) — хранит информацию о пользователях, книгах, рецензиях, покупках и других сущностях системы.
Платёжная система (внешний сервис) — обрабатывает онлайн-платежи, выдаёт подтверждения.
Сервис уведомлений (внешний сервис) — отправляет письма/уведомления по различным каналам (email, SMS, push-уведомления).
Причины выбора базового архитектурного стиля
Модульность и масштабируемость:
Разделение на веб-приложение и API позволяет масштабировать их независимо (горизонтальное масштабирование).
Простота обслуживания:
Отдельный API облегчает обновление бизнес-логики без влияния на фронтенд.
Удобная интеграция:
Наличие REST/JSON-API упрощает взаимодействие с внешними сервисами (платежи, уведомления) и позволяет в будущем подключать мобильные клиенты.
## Диаграмма компонентов
![hPRDRjD058NtUOeXR18fhJUiMBMaHKA2AahfkZB9q5Xox6Wy1bK8YQOK5aLKx5WX91PiqvzGDp_EAyoy4UUE6zUjawfgcerdpjpn_UwSErPM0caB6RRTmYF7QxXXaxEMb9tWgMK9-_toZYDRuPimuABXUv9xShdXjwswqx15qzzmU8UxLlN9KisrFRdrwgNLjWF91QJjgj_k-1xjwD3R2z](https://github.com/user-attachments/assets/f0fab1fe-cfc8-4d70-95f5-7b5ea5591ca4)

Краткое описание основных элементов диаграммы компонентов (API)
Controllers

AuthController: принимает HTTP-запросы, связанные с аутентификацией/авторизацией (регистрация, логин).
ContentController: обрабатывает операции, связанные с контентом (добавление новых глав, редактирование, просмотр).
PurchaseController: отвечает за оформление покупок и взаимодействие с платёжным сервисом.
Services

AuthService: содержит бизнес-логику аутентификации (генерация токенов, валидация пользователя).
ContentService: бизнес-логика по работе с контентом (проверка прав доступа, обработка изменений, версионирование и т.п.).
PurchaseService: логика оформления заказов, списание средств через платёжную систему, учёт покупок в базе данных.
Repositories

UserRepository: операции CRUD над сущностями пользователей.
ContentRepository: операции CRUD над сущностями контента (книги, главы, рецензии).
PurchaseRepository: операции CRUD над сущностями покупок, историей платежей.

Краткое описание основных элементов диаграммы компонентов (WebApp)
Контроллеры (Controllers)

HomeController: обрабатывает запросы для главной страницы, выводит общее меню, приветственную информацию.
AccountController: отвечает за операции входа, выхода, регистрации пользователей.
ContentController: управляет страницами для создания, редактирования и просмотра контента (глав книг, комментариев).
PurchaseController: обеспечивает функциональность оформления покупки, корзины, оплаты.
Frontend Service Layer

Вспомогательный слой, который инкапсулирует логику взаимодействия с API.
Обычно реализуется как сервис/класс, использующий HttpClient для отправки запросов к ASP.NET Core Web API.
Razor Views

Шаблоны (Razor Pages / .cshtml файлы), формирующие динамические HTML-страницы на основе данных, полученных из контроллеров.
HttpClient

Стандартный класс .NET, позволяющий отправлять HTTP-запросы к API (REST/JSON).
Используется во Frontend Service Layer, чтобы скрыть детали реализации HTTP-вызовов от контроллеров.
